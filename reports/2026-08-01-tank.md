## 검증 (현황 실측)

## 1) Monorepo vs multi-repo facade — **권장: Hybrid monorepo + deploy facade**

| 옵션 | 판정 |
|------|------|
| Pure multi-repo | 공유 auth/p10/codex 버전 지옥 지옥. 100모듈 시 거부 |
| Pure monorepo 즉시 전부 이전 | 리스크·시간 과다 (live p1 등) |
| **Hybrid (권장)** | `legion-host` monorepo = shell + `packages/*` + `modules/*` 레지스트리. 기존 live 레포는 **submodule 또는 배포 아티팩트 복사**로 단계 흡수. 단일 도메인 GH Pages 퍼사드 |

**구조 스케치**
```
legion-host/
  apps/
    web-shell/          # GH Pages root (router, chrome, module mount)
    mask-companion/     # React Native / Expo later (BLE bridge)
  packages/
    runtime/            # module contract, event bus
    auth/               # session (anon → TG → wallet)
    p10/                # fictional credits rail ONLY
    codex/              # relics / reObserve / birth hooks
    analytics/          # beacon → worker
    wallet/             # interface + no-op / later viem
    ui-sense/           # shared chrome tokens
  modules/
    p20-saju/           # or symlink to external until migrated
    p21-tarot/
    ...
  registry/modules.json # single source of module IDs
  deploy/gh-pages/      # static export
```

**경계 규칙**
- 모듈은 **packages를 import만**, packages는 모듈을 모름 (단방향)
- track: `ent` | `finance` | `core` — finance 모듈은 p10 FOMO 패키지 import 금지 (lint 게이트)
- 비가역: push / 실지갑 / 실결제 키 = Sovereign y/n

## 2) Module loader (GH Pages / single domain)

**제약**: GH Pages = static only. SSR 없음. 서버권위 필요 시 **CF Worker 병행** (이미 pay/analytics 패턴).

**패턴 (권장 2층)**

### A. Path modules (기본, 기존 pN 흡수 최속)
- URL: `https://host.example/m/p20/` → static tree 그대로
- Shell chrome: top-level only; module은 full page OR iframe sandbox
- **iframe + postMessage contract** = 기존 classic script 전역 const 충돌 회피 (크로스파일 교훈 적용)

### B. ESM micro-frontends (신규 모듈)
- `import('https://host.example/modules/p44/entry.js')` dynamic import
- Shell injects `window.__LEGION__` capabilities (p10, codex, analytics) as **sealed API**
- Manifest:
```json
{
  "id": "p21-tarot",
  "track": "ent",
  "entry": "/m/p21/",
  "mount": "iframe|esm",
  "caps": ["p10", "codex", "share", "analytics"],
  "dna": ["lung", "p10", "share", "disclosure"]
}
```

**Loader flow**
1. Shell loads `registry/modules.json` (+ cache hash)
2. Route `/m/:id` → resolve manifest
3. Capability gate (track + caps)
4. Mount iframe or ESM; handshake `READY` / `AUTH` / `P10_SYNC` / `EMIT`
5. Unmount cleans listeners (memory leak gate)

**Single domain 라우팅**
- GH Pages SPA fallback: `404.html` → shell rehydrate OR pure multi-path static (iframe 방식은 fallback 불필요 — **우선 iframe path**)
- Deep link: `/m/p20/#/draw` 모듈 내부 hash

## 3) Shared services

| 서비스 | 지금 (honest) | 다음 단계 | 소유권 |
|--------|---------------|-----------|--------|
| **auth** | anon UUID localStorage; TG `initData` 미검증 가능 | CF Worker verify initData → HttpOnly session cookie or JWT | 서버 |
| **p10 credits** | **fictional** `p10_balance` localStorage + skim/grant hooks | optional server ledger (still fictional currency) | 클라→서버 이전 시 서버권위 |
| **codex** | 모듈별 로컬 파편 가능 | shared IndexedDB + eventual sync API | client-first → sync |
| **analytics** | legion-beacon → analytics-worker | same + module_id dimension | worker |
| **wallet** | UI demo only (p17) | WalletConnect/viem read-only → later write | never mix with p10 balance |

**API surface (모듈 계약)**
```ts
interface LegionRuntime {
  auth: { userId: string; mode: 'anon'|'tg'|'wallet' };
  p10: { get(): number; grant(n, reason): void; pay(n, reason): boolean };
  codex: { record(item): void; reObserve(id): void };
  analytics: { emit(event, props): void };
  share: { peak(payload): Promise<void> };
  track: 'ent'|'finance'|'core';
}
```

**단일 진실원**: `packages/p10` 하나. 모듈 인라인 p10 금지 (마이그레이션 웨이브).

## 4) Web3 — real on-chain vs fictional (정직)

| 레이어 | 상태 | 규칙 |
|--------|------|------|
| p10 / 가챠 / 재화 | **100% fictional entertainment** | 체인 안 탐. 확률·잔액 서버/클라 명시 disclosure |
| p17 지갑 UI | **demo / simulation** | 실자금 0 |
| 실 on-chain (미래) | 미도입 | 지갑 연결·잔액 조회·(선택) 클레임 NFT/포인트 **별 레일** |
| 결제 | daedalus pay-worker 등 **법정화폐/플랫폼** 경로 가능 | crypto 결제 ≠ p10 잔액 등치 금지 |

**절대 금지 (아키텍처)**
- fictional credits를 “토큰”으로 UI 허위 표기
- 클라가 보낸 가격/당첨을 체인/서버 없이 신뢰
- finance track 화면에 p10 FOMO HUD 혼입

**도입 순서 (나중)**
1. Read-only wallet address bind (identity)
2. Off-chain server maps address → fictional p10 (still not token)
3. Optional on-chain collectible (separate contract, audited) — never odds engine on-chain until needed

## 5) Mask device AI companion

**제품 경계**: 폰 앱(companion) ↔ 마스크(펌웨어) ↔ cloud (optional)

| 링크 | 용도 |
|------|------|
| **BLE** | 페어링, 배터리, 터치/IMU 이벤트, 저지연 명령, 인증 세션 키 교환 |
| **Wi‑Fi** | 펌웨어 OTA, 대용량 모델 번들, 클라우드 세션 미디어 (사용자 명시) |
| **USB** | 공장/디버그 only |

**모델 배치**
- **On-device (필수 기본)**: VAD, wake, 짧은 응답 캐시, 프라이버시 필터(로컬 mute), 초소형 SLM optional
- **Phone app**: 오케스트레이션, 페어링 UX, 로컬 히스토리 encrypted
- **Cloud (opt-in)**: 긴 컨텍스트 LLM/멀티모달 — 토글 기본 OFF, 세션 종료 시 삭제 옵션

**프라이버시 아키텍처**
- 오디오: 기본 **로컬 버퍼 → 의도 확정 전 미전송**; LED/앱 상태 = 녹음 중 표시
- 키: 디바이스 identity + app pairing; cloud 키는 기기 키와 분리
- 데이터 클래스: sensor telemetry / voice transcript / identity — 최소수집, 목적 고지
- dual-track: companion ent UX vs 건강/금융 조언 섞지 않음
- 보안: BLE bonding, firmware signed OTA, no secrets in app repo

**앱 스택 후보**: Expo/RN + BLE (`react-native-ble-plx`); 웹 셸과 `packages/*` 타입/계약 공유 (TS monorepo)
